## Tenses

### Present Tense
Used for habits, general truths, or permanent situations.

**Simple Present**:
```
Subject + V1 (s/es for he/she/it)

I study computer science.
She writes code every day.
Water boils at 100°C.
```

**Present Continuous**:
```
Subject + am/is/are + V-ing

I am learning Python.
They are working on a project.
```

### Past Tense
Used for completed actions in the past.

**Simple Past**:
```
Subject + V2

I studied algorithms yesterday.
She wrote a program last week.
We visited the company yesterday.
```

**Past Continuous**:
```
Subject + was/were + V-ing

I was coding when you called.
They were discussing the problem.
```

### Future Tense
Used for future actions or predictions.

**Simple Future**:
```
Subject + will + V1

I will learn machine learning.
She will finish the project tomorrow.
```

**Future Continuous**:
```
Subject + will be + V-ing

This time next year, I will be working as a developer.
```

### Present Perfect
Connects past to present.

```
Subject + have/has + V3

I have learned Python.
She has completed three projects.
Have you ever visited Silicon Valley?
```

## Conditional Sentences

### Type 0: General Truths
```
If + present simple, present simple

If you heat water to 100°C, it boils.
If the code has errors, the program crashes.
```

### Type 1: Real Possibility
```
If + present simple, will + V1

If I study hard, I will pass the exam.
If you don't debug the code, it won't work properly.
```

### Type 2: Hypothetical Present
```
If + past simple, would + V1

If I had more time, I would learn another language.
If I were you, I would choose machine learning.
```

### Type 3: Hypothetical Past
```
If + past perfect, would have + V3

If I had studied harder, I would have passed the test.
If we had used the algorithm, we would have saved time.
```

## Technical Vocabulary

### Programming Terms
- **Algorithm**: Step-by-step procedure for solving a problem
- **Variable**: Container for storing data values
- **Function**: Reusable block of code
- **Loop**: Structure that repeats code
- **Array**: Collection of elements
- **Debug**: Process of finding and fixing errors
- **Compile**: Convert source code to executable
- **Execute**: Run a program
- **Syntax**: Rules for writing code
- **API**: Application Programming Interface

### Hardware Terms
- **CPU**: Central Processing Unit
- **RAM**: Random Access Memory
- **Storage**: Device for saving data
- **Motherboard**: Main circuit board
- **GPU**: Graphics Processing Unit
- **Peripheral**: External device (keyboard, mouse)

### Network Terms
- **Bandwidth**: Data transfer rate
- **Latency**: Delay in data transmission
- **Server**: Computer providing services
- **Client**: Computer requesting services
- **Protocol**: Set of communication rules
- **Firewall**: Security system

## Reading Comprehension

### Skimming
Quick reading to get the main idea. Read:
- Title and headings
- First and last paragraphs
- First sentence of each paragraph

### Scanning
Looking for specific information. Focus on:
- Keywords
- Numbers and dates
- Names and places

### Reading Technical Texts
1. Read the abstract/summary first
2. Identify the main sections
3. Focus on diagrams and code examples
4. Take notes of key terms
5. Review conclusions

### Example Text
```
Machine Learning in Healthcare

Machine learning (ML) is transforming the healthcare industry. 
By analyzing vast amounts of medical data, ML algorithms can 
predict diseases, recommend treatments, and personalize patient care.

Key applications include:
1. Medical imaging analysis
2. Drug discovery
3. Patient monitoring
4. Predictive diagnostics

However, challenges remain. Data privacy concerns and the need 
for large, labeled datasets are significant barriers. Despite 
these challenges, the potential benefits make ML a promising 
tool for healthcare advancement.
```

**Questions**:
1. What is the main topic?
2. List three applications of ML in healthcare.
3. What are the challenges mentioned?

## Writing: Email & Report

### Formal Email Structure
```
Subject: Clear, specific subject line

Dear [Title] [Name],

Opening: State purpose of email
Body: Explain details clearly
Closing: Request action or response

Best regards,
[Your Name]
[Your Position]
```

### Example Email
```
Subject: Project Progress Report - Week 5

Dear Dr. Smith,

I am writing to submit my weekly progress report for the 
Algorithm Optimization Project.

This week, I have completed:
1. Literature review on sorting algorithms
2. Implementation of quicksort algorithm
3. Initial testing with sample datasets

Next week, I plan to:
- Optimize the algorithm for large datasets
- Compare performance with other sorting methods

Please let me know if you need any additional information.

Best regards,
John Doe
Computer Science Student
```

### Technical Report Structure
1. **Title Page**: Title, author, date
2. **Abstract**: Summary (150-250 words)
3. **Introduction**: Background, objectives
4. **Methodology**: How the work was done
5. **Results**: Findings with data/graphs
6. **Discussion**: Analysis of results
7. **Conclusion**: Summary and recommendations
8. **References**: Cited sources

## Listening & Speaking

### Technical Presentations
**Opening**:
- "Good morning/afternoon everyone."
- "Today I will present about [topic]."
- "This presentation covers [main points]."

**Signposting**:
- "First, let's look at..."
- "Moving on to the next point..."
- "Now, let's consider..."
- "In conclusion..."

**Handling Questions**:
- "That's a good question."
- "Let me clarify that."
- "I don't have that information right now, but I can find out."

### Active Listening Tips
1. Focus on main ideas, not every word
2. Listen for keywords and transitions
3. Take notes of important points
4. Ask for clarification if needed
5. Summarize what you heard

### Common Classroom Phrases
- **Asking**: "Could you explain that again?"
- **Clarifying**: "Do you mean...?"
- **Agreeing**: "I agree with that point."
- **Disagreeing**: "I see it differently."
- **Suggesting**: "How about we try...?"
